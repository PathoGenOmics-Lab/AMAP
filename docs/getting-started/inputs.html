Preparing inputs

AMAP takes assembled genomes. It does not do assembly, so reads are not an input here.

The sample sheet#

A tab-separated file with a header row and exactly two columns:

samples.tsv
sampleId	fasta
G26689	/data/genomes/G26689.fasta
G26690	/data/genomes/G26690.fasta
L4_G12345	./assemblies/L4_G12345.fa
  • sampleId: The name carried through every output directory and file. Must be unique.
  • fasta: Path to the assembled genome. Absolute, or relative to the directory you launch Nextflow from.

The separator has to be an actual tab. Spaces will not do, and this is the most common reason a sample sheet is rejected.

Avoid dots in sample IDs

Several scripts derive the sample name by cutting at the first dot, so G26689.1 becomes G26689 and two such samples would collide. Stick to letters, digits and underscores.

Pre-flight validation#

VALIDATE_INPUTS runs before any computation, on every run. To run only the checks and stop:

nextflow run PathoGenOmics-Lab/AMAP -profile docker \
    --tsv samples.tsv --validate_only

Results are written to results/pipeline_info/validation.log.

What fails the run#

CheckThreshold
Genome sizebelow 100 kb, or above 20 Mb
N contentabove 10%
GC contentbelow 20% or above 80%
Empty sequencesany record with no bases
Duplicate contig headersany repeated identifier
Sample sheetmissing sampleId or fasta column, no data rows, duplicate or empty sample IDs
FASTA pathfile does not exist or cannot be parsed

What only warns#

CheckThreshold
Genome sizebelow 500 kb, or above 10 Mb
N contentabove 1%
GC contentbelow 25% or above 75%
Assembly fragmentationmore than 100 contigs, and again above 500
Short contigsany contig under 200 bp in a multi-contig assembly
Non-standard charactersanything outside ATGCNRYSWKMBDHV

Warnings do not stop a run. Add --strict to the validation step if you want them treated as failures.

The thresholds are deliberately wide, since AMAP is not restricted to tuberculosis. A 4.4 Mb MTBC genome at 65% GC sits comfortably inside them, and so does most of the bacterial world.

Assembly quality#

The correction compares your annotation against a reference proteome, so assembly quality propagates directly into the result.

Contiguity matters. A gene broken across two contigs cannot be recovered. The more fragmented the assembly, the more reference genes turn up as missing rather than corrected.

Ns break coding sequences. A run of Ns inside a gene stops it translating, so it is dropped or flagged as a pseudogene. The 1% warning is worth taking seriously.

Contig names are kept

AMAP runs Bakta with --keep-contig-headers, so the sequence names you supplied are the ones in BAKTA/ and in the corrected annotation, and the corrected tables say which contig each gene is on. Without that option Bakta relabels everything contig_1, contig_2 and so on, and classify_cases.py stops with an error on a multi-contig assembly rather than compare genes across contigs.

Draft assemblies

Every contig of a draft assembly is numbered from 1, so the same coordinates turn up on several contigs. The correction keys every gene on its contig as well as its start, end and strand, only ever compares genes on the same contig, and translates each one from its own contig. Cut into 40 contigs, CDC1551 gets every gene that lies within one contig exactly as the closed genome does.

Reference data#

For MTBC you need nothing else. The container bundles the H37Rv proteome, the Bakta light database, the Mycobrowser table and the pathotypr lineage markers. See containers for the full list.

For any other organism, supply your own reference with --ref_annotation and --ref_genome. See custom reference.

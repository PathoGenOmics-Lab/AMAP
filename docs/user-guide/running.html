Running AMAP

2 min read

Nextflow runs the pipeline straight from GitHub, so there is nothing to clone and nothing to keep up to date by hand.

Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile docker --tsv samples.tsv

Profiles

#

A profile is a bundle of settings. You normally combine one container profile with one executor profile.

ProfileKindWhat it does
dockercontainerRuns every process in the AMAP Docker image.
singularitycontainerSame image via Singularity or Apptainer.
standardcontainerNo container. Every tool must already be on PATH.
slurmexecutorSubmits each process as a SLURM job.
sgeexecutorSubmits to Sun Grid Engine or Univa Grid Engine.
pbsexecutorSubmits to PBS or Torque.
lsfexecutorSubmits to IBM Spectrum LSF.
testdataSmall bundled dataset, for checking the installation.
highmemresourcesRaises the ceilings to 48 CPUs, 256 GB, 120 h.

Combine them with commas:

Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile singularity,slurm --tsv samples.tsv

The order does not matter: each profile sets its own kind of thing. The ceilings on what any one task may ask for come from which profiles are on, not from their order: 48 CPUs, 256 GB and 120 h with highmem, 4 CPUs, 8 GB and 1 h with test, 48 CPUs, 128 GB and 72 h with an executor profile, and otherwise the machine's CPUs, 16 GB and 72 h. Without an executor profile everything runs on the local machine.

On a laptop or workstation

#
Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile docker --tsv samples.tsv

CPUs are auto-detected and memory is capped at 16 GB. Raise both if the machine allows:

Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile docker \
    --tsv samples.tsv --max_cpus 8 --max_memory 32.GB

A handful of genomes is fine locally. Beyond about twenty, a cluster is worth the setup.

On an HPC cluster

#
Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile singularity,slurm --tsv samples.tsv

Each process becomes its own scheduler job, with up to 200 running at once, so Bakta, Miniprot and eggNOG parallelise across all your samples. Defaults reach 48 CPUs and 128 GB per job, and every process carries a time limit so nothing sits in the queue forever.

To match your site's queues and accounting:

Terminal
$ nextflow run PathoGenOmics-Lab/AMAP \
    -profile singularity,slurm \
    --tsv samples.tsv \
    --max_cpus 64 --max_memory 256.GB \
    -process.queue long \
    -process.clusterOptions '--account=mygroup'

Deployment on HPC goes into the details that actually bite: shared filesystems, scratch, and where the eggNOG database should live.

TipLarge datasets

Past a hundred genomes, use a scheduler. The eggNOG step in particular runs once over all samples at a time rather than once per sample, precisely so a shared filesystem is not hammered by hundreds of jobs reading the same Diamond database.

Non-MTBC organisms

#

Lineage typing and Mycobrowser categories are specific to tuberculosis. Turn them off and bring your own reference:

Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile docker \
    --tsv samples.tsv \
    --skip_typing --skip_mycobrowser \
    --genus Escherichia --species "Escherichia coli" \
    --ref_annotation my_reference.gbk --ref_genome my_reference.fasta

See custom reference.

Resuming

#

Nextflow caches every completed task, so an interrupted run picks up where it stopped:

Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile singularity,slurm \
    --tsv samples.tsv -resume

Keep the parameters identical. Changing an input invalidates that task and everything downstream, which is correct behaviour but does mean the work is redone. The cache lives in the work directory, so do not delete it between a run and its resume.

Running only part of the pipeline

#

--skip_functional_annotation stops after the correction step. You get the corrected genes as a table with their proteins and sequences (*.AMAP.tsv, .faa, .fna) and the case tables, and skip eggNOG, duplications, the pangenome and the report. The GFF3 and GenBank files are written after eggNOG, so they are skipped too. Much faster when the corrected genes are all you are after:

Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile docker \
    --tsv samples.tsv --skip_functional_annotation

What a run produces

#

Beyond the results themselves, results/pipeline_info/ holds the execution report, the timeline, the DAG, a trace with per-process resource usage, software_versions.yml with the exact version of every tool, and params.yml with the parameters used. Those last two are what you want when writing up methods.

Describes AMAP on main, ahead of 1.0.1: what changed

Containers

3 min read

Every tool AMAP calls lives in one image, paururo/amap, published on Docker Hub. Both the docker and singularity profiles use it, so nothing needs installing beyond a container engine.

Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile docker --tsv samples.tsv
$ nextflow run PathoGenOmics-Lab/AMAP -profile singularity --tsv samples.tsv

Nextflow pulls the image on first use and caches it. Singularity converts it to an image file of its own on the way, which takes a few minutes once per cache folder: see Singularity on a cluster for keeping one.

What is inside

#

Tools: Bakta 1.12.0, miniprot 0.18, Diamond 2.1.24, eggNOG-mapper 2.1.13, pangene 1.1, pathotypr 1.0.0, gfatools.

Runtimes: Python 3.9 with pandas, NumPy, Biopython, matplotlib, plotly, NetworkX, intervaltree, pyvis and python-louvain. R 4.4 with the report packages.

Bundled data under /reference/, so a standard MTBC run needs no downloads:

FileWhat it is
MTB_ancestor_reference.fastaMTBC ancestral reference genome
aa_H37Rv.translated.fasH37Rv reference proteome
bad.bakta.translated.fasCurated Bakta false positives
new_refH37Rv.fastaH37Rv reference genome
sequence.gbH37Rv GenBank, for Bakta
Mycobacterium_tuberculosis_H37Rv_txt_v4.txtMycobrowser functional categories
snps_lineages.tsvpathotypr lineage markers

Plus the Bakta light database at /data/bakta_db.

The eggNOG database is not bundled, because of its size. AMAP downloads and builds it on first use and caches it at --eggnog_db.

Platform

#

The image is linux/amd64 only, and every Dockerfile stage pins it. On Apple Silicon it runs under emulation, which works but is slow. For anything past a couple of genomes, use an amd64 machine or a cluster.

Pinning a version

#

A tag can move: latest is whatever was pushed last. For a reproducible analysis, pin the image by its digest, and the pipeline's code with -r, since a pinned image under newer code is still a different run:

Terminal
$ nextflow run PathoGenOmics-Lab/AMAP \
    -r 947a99dee49d2a2429e014296ac35ba08e911108 \
    -profile docker --tsv samples.tsv \
    -process.container 'paururo/amap@sha256:08bd17311ab323317ceecba6e5bc639a29f4c54c9d95f9a7c48ba80a9fc640ee'

That digest is the image behind the runs on these pages; docker image inspect paururo/amap:latest --format '{{index .RepoDigests 0}}' prints the one you have. Pinning the pipeline has the rest.

results/pipeline_info/software_versions.yml records the exact version of every tool a run used, which is what belongs in a methods section.

Building it yourself

#

Only needed if you are changing what is in the image.

Terminal
$ git clone https://github.com/PathoGenOmics-Lab/AMAP
$ cd AMAP
$ docker build --platform linux/amd64 -f docker/Dockerfile -t amap:dev .

The build takes about an hour: it downloads the Bakta database and solves a conda environment with R. Check the result before using it:

Terminal
$ docker/smoke_test.sh amap:dev

That verifies the tools, the Python and R libraries, the bundled reference data, and runs the repository test suite with the image interpreter. The last part matters, since a library update can break the pipeline scripts without the image looking any different.

Publishing is automated: the Docker image GitHub Actions workflow builds, smoke tests and pushes on a v* tag or on demand.

WarningReference downloads can expire

Several reference files are fetched from Google Drive during the build. Those links have expired before. If a build fails on a wget in the data stage, that is why, and the URL needs replacing. The Zenodo-hosted files (MTB_ancestor_reference.fasta, the pathotypr markers) are not affected.

Singularity on a cluster

#

The singularity profile keeps the converted image in <outdir>/singularity_cache, so each results folder gets a copy of its own, and that setting wins over NXF_SINGULARITY_CACHEDIR: the variable alone changes nothing. To keep one copy for every run, set the folder in a config and pass it with -c:

shared.config
singularity.cacheDir = '/shared/singularity_cache'
Terminal
$ nextflow run PathoGenOmics-Lab/AMAP -profile singularity,slurm \
    -c shared.config --tsv samples.tsv

With Nextflow 24.04 and 26.10 alike, nextflow -c shared.config config PathoGenOmics-Lab/AMAP -profile singularity then shows cacheDir = '/shared/singularity_cache', where without it the profile's results/singularity_cache stays, whatever the variable says. The pipeline has to be pulled first: any run does it, or nextflow pull PathoGenOmics-Lab/AMAP.

More cluster specifics in deployment on HPC.
